Scientific Paper · SIGMOD 2011

No Free Lunch in Data Privacy

Daniel Kifer, Ashwin Machanavajjhala ACM SIGMOD International Conference on Management of Data · 2011
Abstract Differential privacy has become the gold standard for privacy-preserving query answering over statistical databases. It guarantees that the distribution of noisy query answers changes very little with the addition or deletion of any single tuple. It is frequently accompanied by popularized claims that it provides privacy without any assumptions about the data and that it protects against attackers who know all but one record. This paper critically analyzes these claims. Using a no-free-lunch theorem — which defines non-privacy as a game between an attacker and a data curator — the authors prove it is impossible to provide both privacy and utility without making assumptions about how the data is generated. They then clarify when those assumptions hold (independent tuples), show concrete privacy breaches in social networks and contingency table settings, and propose modifications to differential privacy that account for prior data releases and correlated records.

1. Differential Privacy: The Promise

Differential privacy, introduced by Dwork, McSherry, Nissim, and Smith around 2006, is one of the most celebrated ideas in modern data management. The core guarantee is elegant: if you add noise calibrated to the sensitivity of a query (how much the query answer can change when one record is added or removed), then the output distribution of your algorithm changes only slightly between any two neighboring databases. An attacker who sees the noisy output cannot tell — with much confidence — whether any particular individual's record was included.

Definition — Unbounded Differential Privacy

A randomized algorithm $\mathcal{A}$ satisfies unbounded epsilon-differential privacy if for any set $S$ and any pair of databases $D_1, D_2$ where $D_1$ can be obtained from $D_2$ by adding or removing one tuple: $$P(\mathcal{A}(D_1) \in S) \leq e^\epsilon \cdot P(\mathcal{A}(D_2) \in S)$$ A smaller $\epsilon$ means stronger privacy (but also more noise and less utility). Bounded differential privacy uses the same definition but restricts $D_1$ and $D_2$ to differ by changing exactly one tuple's value (not adding or removing it).

The canonical mechanism for achieving differential privacy is the Laplace mechanism: add noise drawn from a Laplace distribution with scale proportional to the query's sensitivity. For a count query $q(D)$ with global sensitivity 1 (adding one record changes the count by at most 1), the perturbed output is $q(D) + \text{Laplace}(1/\epsilon)$. This adds noise with standard deviation $\sqrt{2}/\epsilon$. For typical values like $\epsilon = 0.1$, this can be substantial noise, but for $\epsilon = 1$ on a large database, the signal-to-noise ratio is often acceptable.

Several bold claims have accompanied differential privacy's rise: "It makes no assumptions about how data are generated." "It protects an individual's information even if an attacker knows about all other individuals in the data." "It is robust to arbitrary background knowledge." This paper examines each of these claims with mathematical precision and shows they are at best misleading, and in some settings, demonstrably false.

2. The Discriminant and Utility

To analyze the trade-off between privacy and utility formally, the paper introduces the concept of a discriminant — a measure of how useful a privacy-infusing query processor actually is.

Definition — Discriminant

Given an integer $k > 1$, a privacy-infusing query processor $\mathcal{A}$, and a constant $c$, we say the discriminant $\omega(k, \mathcal{A}) \geq c$ if there exist $k$ possible database instances $D_1, \ldots, D_k$ and disjoint sets $S_1, \ldots, S_k$ such that for each $i = 1, \ldots, k$: $$P(\mathcal{A}(D_i) \in S_i) \geq c$$ where the randomness is only over $\mathcal{A}$. Intuitively, the discriminant measures how reliably $\mathcal{A}$ can distinguish which of $k$ possible databases it is operating on.

A discriminant close to 1 is good for utility: it means the algorithm reliably gives informative answers that let us distinguish between meaningfully different database states (e.g., "this database has 0 cancer patients" vs. "this database has 10,000 cancer patients"). Algorithms with very low discriminants are essentially useless — their outputs tell us nothing about the data. The discriminant is a lower bound on utility: if the discriminant is close to 1, there exists at least one question the algorithm can answer accurately.

3. The No-Free-Lunch Theorem

The paper formalizes "non-privacy" as a game between a data curator and an attacker. The curator has a database $D$ drawn from some data-generating mechanism $\mathcal{P}$. The curator publishes the output of a privacy-infusing algorithm $\mathcal{A}(D)$. The attacker — who knows $\mathcal{A}(D)$ — then tries to guess the value of some sensitive query $q(D)$. Non-privacy is achieved if the attacker guesses correctly with high probability.

Theorem 2.1 — No Free Lunch

Let $q$ be a sensitive query with $k$ possible outcomes. Let $\mathcal{A}$ be a privacy-infusing query processor with discriminant $\omega(k, \mathcal{A}) > 1 - \epsilon$ for some $\epsilon > 0$. Then there exists a data-generating mechanism $\mathcal{P}$ over database instances $D$ such that $q(D)$ is uniformly distributed but the attacker wins with probability at least $1 - \epsilon$ when given $\mathcal{A}(D)$.

Let's unpack this theorem slowly. It says: if your query processor is at all useful (has a high discriminant), then there exists some data-generating mechanism under which an attacker can completely break privacy. The attacker's strategy is simple: observe the output of $\mathcal{A}$, determine which of the $k$ designated output sets $S_i$ the output falls in, and guess $q(D) = i$. If the discriminant is high, this strategy works well.

The theorem is not an attack on any particular mechanism. It is a universal impossibility result: for any useful mechanism, there is some world in which it fails to provide privacy. The word "some" is crucial — the theorem does not say differential privacy always fails. It says you cannot rule out failure without restricting what kind of world you are in (i.e., without making assumptions about the data-generating mechanism).

The intuition in plain English

Suppose you release a noisy count of cancer patients in a database. If the world is such that the number of cancer patients varies a great deal between databases (say, anywhere from 0 to 20,000), and your noisy count is accurate enough to distinguish between these cases (high discriminant), then an attacker who knows your data-generating mechanism can perfectly reconstruct the count from your noisy answer. The noisy answer is useful precisely because it conveys information — and an attacker who knows which databases were possible can use that same information to learn private facts. You cannot be useful and uninformative at the same time. Privacy without assumptions about the data is a logical impossibility.

4. Non-Privacy and Why Assumptions Are Needed

The no-free-lunch theorem shows that privacy and utility require assumptions. What assumptions does differential privacy implicitly rely on? The paper identifies the key assumption: records are independent of each other.

When records are independent — when each person's data is generated independently of everyone else's — adding or removing one record genuinely changes the database in a limited, localized way. The differential privacy guarantee (that $\mathcal{A}(D_1)$ and $\mathcal{A}(D_2)$ have similar distributions) then means that the attacker cannot infer whether any one person's record was included. Deleting a record removes exactly that person's contribution and nothing else.

But when records are correlated — when one person's data influences others' data — removing a single record from the database does not remove all evidence of that person's participation. The records of correlated others still carry information about the deleted person. In this case, the differential privacy guarantee, which compares databases differing by one record, is too weak: it does not account for the indirect evidence that remains in correlated tuples.

Example — Family disease correlation

Suppose Bob is in a database, and all members of Bob's immediate family have contracted a highly contagious disease. A weaker attacker who knows nothing about the family's health can ask "how many people in Bob's family have this disease?" The answer is almost certainly 0 or 10 (the family size). Adding Laplace noise at level $1/\epsilon$ produces a noisy answer, say 12. This noisy answer is $e^{10\epsilon}$ times more likely when the true answer is 10 (Bob is sick) than when it is 0 (Bob is healthy). A stronger attacker who already knows that 9 family members are sick can update their belief by a factor of at most $e^\epsilon$ — differential privacy does limit the stronger attacker's inference. But it does not limit the weaker attacker's inference. More counterintuitively, protecting against stronger (more informed) attackers does not always protect against weaker ones when data are correlated.

5. Evidence of Participation

The paper proposes a key conceptual distinction: the difference between the presence of a tuple in a database and the participation of an individual in the data-generating process. Differential privacy limits inference about the former. What matters for genuine privacy is limiting inference about the latter.

In a world of independent records, these two things coincide: if Alice did not participate, her tuple is not in the database, and vice versa. But in a social network, Bob's participation (his actions, friendships, communications) affects other people's records. Bob's friendship causes edges to form between his contacts. Even if you delete the tuple "Bob" from the network, the edges between his former contacts — edges that Bob caused to form — remain as evidence of Bob's participation. Differential privacy by deleting one tuple (Bob's node) does not hide those edges.

The paper proposes a guideline for evaluating privacy mechanisms: can the mechanism hide the evidence of an individual's participation from an attacker who had little prior information about that participation? This is called the participation-based guideline. When tuples are independent, this guideline reduces to standard differential privacy. When tuples are correlated, stronger guarantees are needed.

6. Social Networks: Where Differential Privacy Fails

Section 3 of the paper makes the abstract argument concrete by simulating three popular social network generation models: the Forest Fire model (Leskovec et al.), the Copying model, and the MVS (Marsili-Vega-Redondo-Slanina) model.

The setup is this. Suppose a social network has two communities that initially do not interact (they share at most one edge). Bob has an edge to someone in Community 2. This edge causes friends-of-friends links to form: Bob introduces Alice to Charlie, who introduces more people, and so on. The network grows according to one of the three models. The question is: how different is the expected number of cross-community edges in a network where Bob's initial edge exists versus a network where it does not?

Under the Forest Fire model with typical parameters, after the network grows to 50 nodes, the expected number of cross-community edges with Bob's initial edge is approximately 240, versus approximately 119 without it. The difference $Y = 240 - 119 = 121$. To hide Bob's initial edge with $\epsilon$-differential privacy, you would need to add Laplace noise of scale $Y/\epsilon$ to the cross-community edge count — adding over 1200 units of noise for $\epsilon = 0.1$. For a network of only 50 nodes with roughly 119 cross-community edges, this noise completely drowns the signal, making the query answer useless. Any meaningful answer would reveal Bob's participation.

The catch with unknown network models

The correct noise level $Y$ depends on the network generation model and its parameters. But in practice, we do not know which model generated the network or what the parameters are. You cannot set $\epsilon$ reliably without knowing $Y$, and you cannot know $Y$ without knowing the model. This means you cannot apply differential privacy meaningfully to social network data without assuming you know how the network was generated. The "no assumptions" claim is refuted: assumptions are unavoidable.

7. Contingency Tables: The Prior-Release Problem

Section 4 addresses a second setting where differential privacy's guarantees break down: when deterministic statistics about the data have been previously released. This is a realistic scenario — government agencies routinely release exact marginal counts before applying differential privacy to finer-grained queries.

The key example: a table $T$ has one attribute $R$ taking values $r_1, \ldots, r_k$. Suppose $k - 1$ disjunctive count queries have been answered exactly: each query gives the count for two values of $R$ combined. This does not allow exact reconstruction of the table (there are $k$ unknowns but only $k - 1$ linear equations). Now, an analyst also wants the individual counts, answered with differential privacy noise.

The problem is that the previous exact answers create correlations between the noisy answers to the new queries. Each noisy answer leaks a small amount of information about each count. By averaging multiple noisy estimates (derived via simple linear algebra from the exact previously-released answers plus the new noisy answers), an attacker can estimate any individual count with variance $2/(k\epsilon^2)$ rather than the expected $2/\epsilon^2$. When $k$ is large (for example, $k = 2^d$ for a $d$-bit attribute), the variance becomes negligible and the entire table can be reconstructed with high probability — a complete privacy breach.

The paper's proposed solution is generalized differential privacy with induced neighbors. Rather than comparing all pairs of databases that differ by one record (the standard neighbor relation), the algorithm is required to be stable between pairs of databases that are "as similar as possible" subject to consistency with the previously released query answers. This makes the noise calibration depend on the prior statistics, preventing the averaging attack.

8. What the Paper Recommends

Rather than abandoning differential privacy, the paper offers constructive guidance:

For independent records (each person's data generated independently of others'), differential privacy is well-suited. Deleting one record genuinely hides that person's participation. The independence assumption is reasonable for many standard tabular datasets (medical records, survey data without social network effects). Use it confidently.

For correlated data (social networks, family health data, spatially correlated geographic data), the evidence of participation depends on the data-generating mechanism. You must either (a) model that mechanism explicitly and calibrate noise accordingly, or (b) accept that differential privacy provides a weaker guarantee than advertised, or (c) use the participation-based guideline to choose a definition of neighbors appropriate to your setting.

For prior data releases, use the induced-neighbor formulation of differential privacy that accounts for previously released exact statistics. The paper provides efficient algorithms (based on the exponential mechanism and a modified Laplace mechanism) for this generalized setting, though computing the sensitivity in the fully general case is NP-hard, and efficient special cases (e.g., 2-dimensional contingency tables with fixed row and column sums) are characterized.

9. Lasting Impact

This paper, along with related work by Dwork and Naor that it builds on and simplifies, fundamentally shifted the conversation about what differential privacy does and does not guarantee. Before this paper, it was common to hear researchers describe differential privacy as assumption-free. After this paper, the community broadly accepted that differential privacy's guarantees are conditional on the independence assumption, and that applying it to social networks or databases with prior releases requires more care.

The participation-based guideline influenced subsequent privacy definitions for graph data. The notion of "edge differential privacy" (making the mechanism stable to the addition or removal of a single edge, rather than a single node) is one response to the concerns raised here. Later work on Pufferfish privacy (Kifer and Machanavajjhala, 2014) developed a general framework that makes the data-generating model explicit and required, directly formalizing the lesson of this paper: privacy guarantees must be relative to a stated model of how the data came to be.

In the age of large-scale machine learning and data-driven systems, the paper's core message is more relevant than ever. Federated learning systems, synthetic data generators, and query interfaces that claim differential privacy guarantees all implicitly rely on assumptions about independence. The no-free-lunch theorem is a permanent reminder that there is no privacy mechanism that is universally correct without knowing something about the world the data came from.
