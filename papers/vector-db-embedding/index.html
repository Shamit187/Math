SIGMOD 2025 · Research Paper

Integrating Vector Databases across Embedding Models

Beining Yang, Yang Cao, Yang Ren Proc. ACM Manag. Data (SIGMOD), Vol. 3, No. 6, Article 338, December 2025 University of Edinburgh & Edinburgh Research Center, Huawei
Abstract Vector databases are the engine behind modern similarity search — retrieving documents, images, or other unstructured data objects by finding vectors that are geometrically close to a query. Every vector database is produced by an embedding model that converts raw objects into high-dimensional vectors, with the guarantee that similar objects land near each other. The catch: different organizations routinely use different embedding models, so their vector databases live in entirely different geometric universes that cannot be naively merged. This paper asks: can we combine vector databases that were built with different embedding models, without re-embedding the data and without access to the models themselves? The authors say yes — rooted in a newly discovered phenomenon called the local isometry hypothesis: even if two embedding spaces disagree globally, they agree locally on which items are most similar. Building on this, they propose LA2M (Localized Align-to-Merge), an algorithm that uses a set of reference vectors — items encoded by both models — to stitch the two spaces together cluster by cluster. Theoretical bounds on the integration error and experiments on five major embedding models (NV-Embed-V2, OpenAI Ada, GloVe, Mistral, FastText) demonstrate high recall of top-k similarity search over the merged databases.

1. Introduction

Similarity search over unstructured data — finding images that look alike, documents that discuss the same topic, or products that share features — is the backbone of recommender systems, retrieval-augmented generation (RAG) for large language models, and privacy-preserving federated search. The standard implementation encodes each data item as a vector using an embedding model, then answers a query by finding the vectors geometrically nearest to the query vector — a top-k nearest-neighbour search. The collection of all encoded vectors is the vector database.

Intuition — Why this problem is hard

Think of an embedding model as a secret translator. It converts every object into a point in some high-dimensional space. Two different translators may choose completely different coordinate systems — rotating, reflecting, stretching, and re-arranging the whole space — even if both translators faithfully capture the same underlying similarity relationships. Simply stacking the two sets of points in one database is like superimposing two city maps drawn at different scales and orientations: a search query will point to random locations that have nothing to do with actual similarity.

The inability to share vector databases is a stark contrast to relational databases, where different systems routinely share and integrate tables via SQL joins and federated queries. The paper calls out three concrete applications that motivate breaking this barrier:

  • Embedding backfilling. When a company upgrades its embedding model, historical vectors are incompatible with the new model. Backfilling requires re-embedding every document, which is expensive. Integration would let old and new vectors coexist searchably.
  • Privacy-preserving federated search. Multiple organizations each hold private data embedded with their own models. They want a collective search without revealing raw data. Integration allows sharing only the vectors.
  • Cloud-edge similarity search. An edge device (phone, camera) uses a lightweight local model; the cloud uses a more powerful one. Sending the raw image to the cloud is expensive and private. Sending just an embedded query vector is far cheaper.

The authors impose a strict constraint: the integration algorithm may only see the embedding vectors themselves. It cannot re-embed the data objects, cannot query the embedding models, and has no access to the model weights or architectures. This makes the problem genuinely hard and industrially realistic.

2. Background and Definitions

Definition — Vector Database

Let $\mathcal{U}$ be a universe of data items (documents, images, etc.) with a dissimilarity function $d_{\text{sim}}$ that tells us how different any two items are. An embedding function $\text{emb}$ maps each item $o \in O$ to a vector $\text{emb}(o) \in \mathbb{R}^d$ such that the Euclidean distance $\|x_1 - x_2\|$ approximates $d_{\text{sim}}(o_1, o_2)$. The vector database $\text{emb}(O)$ is the set of all embedded vectors for items in $O$.

Definition — Top-k Similarity Search

Given a query item $o_q$, find the $k$ items in $O$ most similar to $o_q$ under $d_{\text{sim}}$. In practice this is implemented as finding the $k$ vectors in $\text{emb}(O)$ nearest to $\text{emb}(o_q)$ — i.e., top-k approximate nearest neighbour (ANN) search.

Definition — Vector Database Integration

Let $D_1$ and $D_2$ be vector databases for datasets $O_1$ and $O_2$ built with embedding functions $\text{emb}_1$ and $\text{emb}_2$, respectively. An integration function $T$ takes $D_1$ and $D_2$ as input (vectors only — no raw objects, no models) and returns a single vector database $T(D_1, D_2)$ for the union $O_1 \cup O_2$ that supports accurate top-k similarity search.

Key tools used: ANN indices

Vector databases use specialised index structures to answer top-k queries quickly at scale without scanning every vector. Two widely used ones appear in this paper:

  • FAISS / IVF (Inverted File Index). Clusters vectors into Voronoi cells; a query searches only the nearest cells rather than the whole database. Think of it as a postal code system: you only look in the right neighbourhood.
  • HNSW (Hierarchical Navigable Small World). Builds a multilayer graph where each vector is linked to its closest neighbours at various scales. Queries navigate the graph greedily. LA2M can transform HNSW indices directly because it uses distance-preserving maps (isometries).

Why two vector databases cannot be naively merged

Suppose you take $D_1$ (FastText embeddings, 300-dimensional) and $D_2$ (NV-Embed-V2 embeddings, 4096-dimensional) and simply concatenate the two lists of vectors into one big database. A query vector from $\text{emb}_2$ will only ever find $D_2$ vectors as nearest neighbours, because $D_1$ vectors live in an entirely different geometric region — their coordinates are not comparable. Even if the dimensions matched, the coordinate axes would mean different things to each model.

Intuition — The Encryption Analogy

Each embedding model "encrypts" data with its own key. The encryption preserves relative ordering (similar items stay close), but the ciphertexts from different keys look completely unrelated. Integration is like finding a "rosetta stone" that reveals how the two ciphertext spaces relate to each other, without knowing either key.

3. The Isometry Hypothesis

The central intuition behind the paper is that, even though two embedding models produce different vector spaces, they both capture the same underlying similarity structure. If true, the two spaces would be isometric — related by a rigid transformation (rotation, reflection, translation, and uniform scaling) that preserves all distances exactly.

Definition — Isometry

Two sets of vectors $X$ and $Y$ are isometric if there exists a bijection $f: X \to Y$ that preserves all pairwise distances: for every $x_1, x_2 \in X$, $$\|f(x_1) - f(x_2)\| = \|x_1 - x_2\|.$$ Intuitively, isometric sets have the same "shape" — one is just a rotated, reflected, or translated copy of the other.

Hypothesis A — Global Isometry Hypothesis

(1) The geometry of two vector databases $D_1$ and $D_2$ built from the same set of objects $O$ by different embedding functions are likely isometric. (2) If $\text{emb}_1$ and $\text{emb}_2$ produce isometric databases for $O$, they will also likely produce approximately isometric databases for items close to those in $O$.

This hypothesis is analogous to a well-known finding in NLP: word embedding models (Word2Vec, GloVe) trained on different corpora produce vectors that are related by a single global linear transformation. Cross-lingual word embedding alignment exploits exactly this property.

The Align-to-Merge (A2M) framework

If Hypothesis A holds, integration becomes straightforward via a simple strategy called Align-to-Merge (A2M):

  1. Identify reference vectors: items $O_\cap = O_1 \cap O_2$ encoded by both models. Call their vectors $X \subset D_1$ and $Y \subset D_2$.
  2. Compute the best isometry $f_{\text{iso}}$ that maps $X$ to $Y$.
  3. Apply $f_{\text{iso}}$ to all vectors in $D_1$, then combine $f_{\text{iso}}(D_1)$ with $D_2$.

The isometry takes the form $f(x) = s \cdot R(x + \mathbf{t})$ , where $R$ is an orthogonal matrix (rotation/reflection), $\mathbf{t}$ is a translation vector, and $s$ is a uniform scaling factor. Finding the best such function reduces to minimising:

$$\arg\min_{s,\, R,\, \mathbf{t}} \sum_{i=1}^{m} \|s R(x_i + \mathbf{t}) - y_i\|^2$$

This is a classical Procrustes problem from computer vision, with a closed-form solution via Singular Value Decomposition (SVD). Let the SVD of $YX^\top$ be $U\Sigma V^\top$. Then:

  • $R_{\text{opt}} = UV^\top$
  • $s_{\text{opt}} = \text{trace}(\Sigma) / \text{trace}(X^\top X)$
  • $\mathbf{t}_{\text{opt}} = \bar{y} - \bar{x}$ , the difference of the two centroid vectors.
Check your understanding

Why is the optimal rotation given by $UV^\top$ from the SVD of $YX^\top$? Hint: write the sum-of-squares as a trace and use the cyclic property of trace. The key insight is that maximising $\text{trace}(R \cdot XY^\top)$ over orthogonal $R$ has the closed-form solution $R = UV^\top$.

Why A2M fails in practice

Experiments on the SciFact benchmark reveal that A2M does not improve — and sometimes hurts — recall@100 versus a naive "Union" baseline that just concatenates the two databases without any transformation. The Union baseline guarantees finding items from $D_2$ (since the query is in $D_2$'s space and $D_1$ vectors are far away and ignored). A2M moves $D_1$ vectors close to $D_2$, but if the isometry is imperfect, it can introduce noise that pushes $D_2$ answer vectors out of the top-k results.

A CIFAR-10 visualisation in the paper shows that even the same image dataset produces clearly non-isometric shapes when embedded by ResNet vs. DenseNet — clusters are rotated, deformed, and their relative positions are rearranged. The hypothesis does not hold globally.

Key Finding

Global isometry is too optimistic. Real-life embedding models produce vector databases that are geometrically inconsistent at the global scale — different embeddings disagree on which clusters are close to which. A single global transformation cannot reconcile them.

4. Local Isometry and the LA2M Algorithm

While the global hypothesis fails, the experiments reveal a crucial silver lining: for short inter-vector distances — the distances that matter most for small-k queries — different embedding models agree remarkably well. Measuring the Jaccard index between the top-k results of NV-Embed-V2 and OpenAI-Ada on SciFact, the paper finds:

  • For $k=1$ or $2$, Jaccard index approaches 1.0 — the two models almost always agree on the nearest neighbour.
  • For $k=100$, agreement drops significantly — the models diverge on which 100 documents are most similar.
Hypothesis B — Local Isometry Hypothesis

The global isometry hypothesis (Hypothesis A) holds within local regions of vector databases comprised of vectors with short pairwise distances. In other words, embedding models may disagree on the global geometry but tend to agree on who the nearest neighbours of any given item are.

Intuition — Why local isometry holds

Imagine two maps of the same city, drawn by different cartographers using different coordinate projections. Globally, the maps look different — north is up on one but rotated 30 degrees on the other, and the scale is different across regions. But if you zoom into a single neighbourhood, both maps show the same streets in the same relative positions. The local geometry is preserved even when the global picture disagrees. Embedding models are similar: each model has its own "projection" of the semantic space, but locally — in the neighbourhood of any given document — they largely agree on which documents are most similar.

The LA2M Algorithm (Localized Align-to-Merge)

LA2M exploits Hypothesis B by partitioning the reference vectors into small local clusters and computing a separate isometry for each cluster. The algorithm operates in three steps:

LA2M — Step 1: Grouping

Partition the reference vectors $X \subset D_1$ into clusters $X_1, \ldots, X_n$, each containing vectors with short inter-distances (i.e., locally close vectors). The matching $D_2$ reference vectors are partitioned identically: $Y_1, \ldots, Y_n$. The clusters may overlap.

LA2M — Step 2: Alignment

For each pair $(X_i, Y_i)$, compute a local isometry $f^i_{\text{iso}}$ by invoking the A2M Procrustes solution (Section 3). By Hypothesis B, because $X_i$ has short inter-distances, this local isometry should be accurate.

LA2M — Step 3: Merging

For each vector $x \in D_1$:

  • If $x$ is a reference vector in cluster $X_i$, map it directly to its counterpart $y \in Y_i$.
  • If $x$ is a non-reference vector, find the cluster $X_{j^*}$ whose centroid $c_{j^*}$ is closest to $x$, then apply $f^{j^*}_{\text{iso}}(x)$. The nearest-centroid assignment is: $$j^* = \arg\min_{i \in [1,n]} \|c_i - x\|$$

The integrated database is $T(D_1) \cup (D_2 \setminus Y)$ . Query vectors use $\text{emb}_2$ as the ambient space.

Example — Querying an Integrated Database

Suppose Alice has 10,000 scientific papers embedded with FastText ($D_1$) and Bob has 8,000 papers embedded with NV-Embed-V2 ($D_2$). They share 2,000 papers in common ( $O_\cap$), giving reference pairs $(X, Y)$.

  1. LA2M clusters $X$ into, say, 50 local groups of ~40 papers each.
  2. For each group, it computes a local rotation+scale+translation that aligns FastText vectors to NV-Embed-V2 vectors.
  3. Alice's 8,000 non-reference FastText papers are each assigned to their nearest reference cluster and transformed using that cluster's isometry.
  4. The merged database contains 18,000 paper vectors all in NV-Embed-V2's geometric space.
  5. Bob sends Alice a query vector using NV-Embed-V2. Alice searches the merged database and finds relevant papers from both collections — without either party ever seeing the other's raw paper text.

Benefits and Properties

LA2M has two important structural properties that make it practical:

  • Model and object oblivious. LA2M only sees the embedding vectors, never the original data objects or the models. This makes it suitable for privacy-sensitive scenarios.
  • Vector index invariant. Because LA2M uses isometries (which preserve all distances), it can directly transform vector indices (IVF, HNSW) built on $D_1$ into the integrated space, avoiding the need to rebuild the index from scratch.

5. Theoretical Analysis — Error Bounds

The paper provides a theoretical handle on why and how LA2M can fail or succeed. It identifies two types of error that arise from integrating non-reference vectors.

Definition — Alignment Error and Integration Error

For a local cluster pair $(X_i, Y_i)$:

  • Alignment error $\alpha$: how well the computed isometry $f^i_{\text{iso}}$ aligns the reference vectors $X_i$ to their targets $Y_i$. This is the residual of the Procrustes fit — inherent model disagreement that no isometry can eliminate.
  • Integration error $\beta$: for a non-reference vector $x$, the distance between its transformed position $T(x)$ and the ideal position $\text{emb}_2(o_x)$ (where $o_x$ is the data item $x$ encodes). This is the "generalisation error" of applying a cluster's isometry to out-of-cluster vectors.
Theorem 1 — Upper Bound on Integration Error

Let $\hat{X}$ be the mean-centered reference matrix for a cluster. Let its minimum non-zero singular value be $\sigma_{\min}(X)$. Let $\alpha$ be the alignment error and $\alpha^*$ be the residual of the ideal isometry. Then for a non-reference vector $z$ near the cluster:

$$\delta(z) \;\leq\; \frac{\alpha + \alpha^*}{\sigma_{\min}(X)} \cdot \|z - c_X + c_Y\|$$

Here $c_X$ and $c_Y$ are the centroids of $X$ and $Y$.

Let's unpack what each factor in this bound means:

  • $\alpha + \alpha^*$ — the total alignment error. This is the inherent model disagreement: how much the two embedding models disagree on the reference vectors. You cannot control this — it's a property of the embedding models.
  • $1/\sigma_{\min}(X)$ — the inverse of the smallest singular value of the reference cluster matrix. This is the conditioning factor. A well-conditioned reference cluster (large $\sigma_{\min}$) leads to small error amplification. A poorly conditioned cluster (small $\sigma_{\min}$) — e.g., a cluster where all reference vectors lie on a thin line — amplifies the error catastrophically.
  • $\|z - c_X + c_Y\|$ — how far the non-reference vector $z$ is from the cluster centroid. The further $z$ is from the references used to compute the isometry, the less accurate the integration. This is the classic bias-variance tradeoff: large clusters have high alignment error but low amplification of that error to distant points; small clusters have low alignment error but high sensitivity when applied to points far from the cluster.
Intuition — The Conditioning Constraint

Imagine trying to determine the exact orientation of a rigid book by observing only a few reference points on its cover. If all your reference points lie on a single line (the spine), you have no information about rotations around that line — the isometry is ambiguous and the error can be huge. But if your reference points span the full 2D surface of the cover, you can determine the orientation precisely. The minimum singular value $\sigma_{\min}$ measures exactly how well the reference cluster "spans" the relevant directions.

Design Implications (I1–I4)

Theorem 1 gives four practical guidelines for designing LA2M:

  • (I1) Minimising alignment error $\alpha$ is beneficial. Smaller clusters tend to have lower $\alpha$ (local isometry holds better).
  • (I2) But making clusters too small hurts, because $\sigma_{\min}$ shrinks (the cluster becomes rank-deficient) and the error amplification $1/\sigma_{\min}$ blows up.
  • (I3) Directions in the reference cluster with low variance (small $\sigma_i$) are most susceptible — these are the directions the isometry cannot determine accurately.
  • (I4) Non-reference vectors far from the cluster centroid suffer more. This means the nearest-centroid assignment in Step 3 of LA2M is natural: use the cluster that is geographically closest.

6. Algorithm Design Details

Determining cluster scope via intrinsic dimension

The bound in Theorem 1 implies a tension: smaller clusters improve local isometry accuracy ($\alpha$ decreases) but degrade conditioning ($\sigma_{\min}(X)$ shrinks). From (I2), the size $|X|$ of a cluster should be at least $d$, the ambient dimension of the embeddings. But real embeddings have very high $d$ (OpenAI-Ada is 1536, Mistral is 1024), so requiring $|X| \geq d$ would force large clusters and inflate alignment error.

The paper's resolution: choose the cluster size to match the data's intrinsic dimension rather than its ambient dimension. The intrinsic dimension is the minimal number of directions in which the data actually varies — usually far smaller than the ambient $d$.

MLE intrinsic dimension estimator (Levina–Bickel)

For each data point $x_i$, look at its $K$ nearest neighbours and estimate the local intrinsic dimension as:

$$\hat{d} \;=\; \left[\frac{1}{N(K-1)} \sum_{i=1}^{N} \sum_{j=1}^{K-1} \log \frac{T_K(x_i)}{T_j(x_i)} \right]^{-1}$$

where $T_j(x_i)$ is the distance from $x_i$ to its $j$-th nearest neighbour. The paper sets $N = 10$, $K = 20$ per dataset. Experiments (Fig. 7) confirm that recall@100 peaks exactly when $|X|$ matches this intrinsic dimension.

Handling rank-deficient references via PCA

Once the intrinsic dimension $\hat{d}$ is set, clusters are typically smaller than the ambient dimension and so $X$ becomes rank-deficient — directly exacerbating the conditioning problem from (I3). The paper handles this by computing the SVD of each cluster's reference matrix and projecting both $X$ and $Y$ into their respective $\hat{d}$-dimensional subspaces:

$$\hat{X} = X V_X^{\hat{d}}, \qquad \hat{Y} = Y V_Y^{\hat{d}}$$

where $V_X^{\hat{d}}$ and $V_Y^{\hat{d}}$ are the top $\hat{d}$ right singular vectors. The isometry is fit on the projected vectors, and a new non-reference vector $z$ is reduced by $\hat{z} = z V_X^{\hat{d}}$, transformed by $\hat{f}_{\text{iso}}$, then lifted back via $V_Y^{\hat{d}\,\top}$. This also conveniently handles non-square dimensions across models (e.g. FastText 300-dim vs NV-Embed-V2 4096-dim) — both are projected into the shared $\hat{d}$-dim subspace before alignment.

Online integration

LA2M is split into an offline preprocessing pass (Steps 1–2: grouping references, fitting local isometries) and an online step (Step 3: transforming non-reference vectors as they arrive). The offline pass materialises the $n$ local isometries $f^1_{\text{iso}}, \ldots, f^n_{\text{iso}}$ as a small auxiliary vector database keyed by cluster centroids. When a new vector $x$ is added to $D_1$, LA2M does a top-1 search over the centroids to find the right isometry and applies it — making online integration cheap and incremental.

Generating reference vectors when none are given

In many scenarios — backfilling, data linkage, domain knowledge — reference vectors are naturally available. In privacy-sensitive federated settings they are not. The paper specifies an active sampling algorithm parameterised by $L$, the number of local isometries we want, and $\gamma$, the fraction of items to use as references:

  1. Cluster the source database $D$ into $L$ groups via k-means.
  2. From each cluster $C_i$, uniformly sample $\gamma \cdot |C_i|$ vectors as reference candidates $\mathcal{X}$.
  3. Query the target party's embedding model with the corresponding data items to obtain matching vectors $\mathcal{Y}$. The pair $(\mathcal{X}, \mathcal{Y})$ serves as input to LA2M.

Experiments (Fig. 8) show LA2M's cluster-stratified sampling consistently beats uniform random sampling and is robust: dropping $\gamma$ from 80% to 20% raises integration error by only ~3%. When even querying the target model is forbidden, the paper suggests synthesising reference items (e.g., from a diffusion model) — works best when the source database itself was generated that way.

7. Experiments

Experimental setup

The paper evaluates on six major embedding models spanning small to large scale: GloVe (300-dim, trained), FastText (300-dim, trained), NV-Embed-V2 (1024-dim, fine-tunable), GTE-Qwen2 (1024-dim, fine-tunable), OpenAI-Ada (1536-dim, no training), and Mistral (1024-dim, no training). Five text retrieval benchmarks are used: SciFact (5,183 docs, fact-checking), NFCorpus (3,633 docs, biomedical), ArguAna (8,674 docs, counter-arguments), SciDocs (25,657 docs, citation prediction), and FiQA-2018 (57,638 docs, financial Q&A). Each dataset is split so that $O_\cap$ contains one-third of all documents.

The paper reports four quality measures, each capturing a different facet of integration quality:

  • Recall@k: fraction of benchmark queries for which the ground-truth answer is within the top $k$ of the integrated database.
  • Recall@k[$D_1$]: recall@k restricted to queries whose answer lives in $D_1$ only. This eliminates "free credit" — since half the benchmark answers sit in $D_2$, Union can score ~50% recall just by ignoring $D_1$ entirely. Recall@k[$D_1$] is the honest measure of whether integration actually surfaces $D_1$'s items.
  • Relative NDCG: ranking-quality score relative to the ground-truth database $D_* = \text{emb}_2(O_1 \cup O_\cap \cup O_2)$. Captures rank changes, not just hits.
  • Integration error $\beta$: average distance between $T(\text{emb}_1(o))$ and the ideal $\text{emb}_2(o)$ in $D_2$'s space — a direct geometric measure of how well the integration places each vector.

Experiments ran on an AMD EPYC 7713P (120 GB RAM) with an NVIDIA A100 80 GB GPU.

Baselines compared

  • Union: naive union of the two vector databases without any transformation.
  • A2M: global isometry alignment (Procrustes) — Hypothesis A.
  • GW: Gromov-Wasserstein based alignment (optimal transport).
  • CCA: Canonical Correlation Analysis alignment.
  • A2MMLP: A2M with a neural MLP as the alignment function instead of a linear isometry.
  • LA2MMLP: Localized A2M with MLP per cluster.
  • LA2M: the proposed algorithm (localized Procrustes isometries).

Main results

The headline result from Table 1: for integrating FastText into NV-Embed-V2 on SciFact, Union achieves 26.3% recall@100, A2M achieves 18.3% (worse than Union), and LA2M achieves 76.7% — nearly three times the Union baseline. Similar dramatic improvements appear across all model pairs and benchmarks:

  • NV-Embed-V2 into OpenAI-Ada: Union 32%, A2M 32%, LA2M 79% on SciFact.
  • GTE-Qwen2 into NV-Embed-V2: Union 32%, A2M 32%, LA2M 85% on SciFact.
  • Mistral into OpenAI-Ada: Union 32%, A2M 27%, LA2M 77% on SciFact.
Why does LA2M so dramatically outperform A2M?

A2M computes a single global isometry — think of trying to fit a single rigid rotation to a world map that has been distorted differently in every country. LA2M fits a separate local isometry to each neighbourhood. In each small region, the local geometry is well-behaved (Hypothesis B holds), so the fit is accurate. The gain isn't just incremental; it's transformative because top-k search is dominated by the nearest neighbours, exactly the local structure that LA2M captures.

Why isometries beat MLPs (LA2M vs LA2MMLP)

Tables 4–9 also report LA2MMLP, where each local alignment is a 2-layer MLP trained on the reference pairs. Despite higher expressiveness and often lower alignment error on the references themselves, LA2MMLP consistently underperforms plain LA2M on recall and NDCG. The reason: isometries preserve top-k search results over $D_1$ (Theorem 1 guarantees bounded $\delta$), whereas a nonlinear MLP can rearrange distances and lose neighbour structure even when it fits references well. Expressiveness without distance preservation is the wrong trade for retrieval.

Ceiling on absolute recall

LA2M's relative gains are dramatic, but absolute recall is still bounded by each embedding model's native retrieval quality on the benchmark. FastText alone achieves only ~17% recall@100 on NFCorpus regardless of integration — that's a property of FastText's representation, not of the integration method. Two factors put a ceiling on what any integration approach can achieve: (a) the intrinsic difficulty of the benchmark for the chosen embedding model, and (b) the inherent model disagreement between $\text{emb}_1$ and $\text{emb}_2$ (e.g., GloVe vs FastText were trained on very different corpora with different tokenisation, so they encode different similarity).

Impact of reference vector ratio

The paper varies the fraction $\gamma$ of reference vectors from 20% to 80% and compares LA2M's own reference selection strategy against uniform random sampling. Key findings:

  • LA2M's reference selection consistently outperforms random sampling.
  • LA2M is robust: dropping from 80% to 20% references increases integration error by only ~3%.
  • Even with 20% references, LA2M substantially outperforms Union.

Validating local vs. global isometry

To confirm the local isometry hypothesis, the paper evaluates a variant of LA2M that uses $k$-means clustering with varying $k$:

  • As $k$ increases (smaller clusters), alignment error $\alpha$ decreases — local isometry holds better.
  • But at very large $k$, recall@100 drops, because tiny clusters are poorly conditioned and cannot reliably transform non-reference vectors.
  • The sweet spot is intermediate cluster sizes — validating the theoretical trade-off from Theorem 1.

Image search case study

The paper demonstrates privacy-preserving image search on CIFAR-10: Alice uses DenseNet embeddings, Bob uses ResNet embeddings. After LA2M integration, top-1 image search gives the correct category for all 10 test queries. The Union baseline fails 9 out of 10 times, returning semantically unrelated images.

8. Related Work

The paper relates to three main areas of prior work:

Cross-lingual word embedding alignment

A large body of NLP work aligns word embeddings across languages — mapping English word vectors to French word vectors so that "cat" and "chat" end up close together. Methods include supervised Procrustes, Gromov-Wasserstein optimal transport, CCA, and adversarial training. These methods exploit a key property discovered by Mikolov et al.: word embeddings exhibit near-global geometric similarity across languages, so a single linear transformation suffices.

This is fundamentally different from the vector database integration problem. Vector databases — especially for sentence embeddings or images — do not have global geometric regularity. Moreover, cross-lingual alignment aims to match the global distribution of word vectors, while LA2M targets top-k retrieval accuracy, which demands local precision, not global correspondence.

Vector database efficiency

Much prior work on vector databases focuses on efficiency: faster ANN search via FAISS, ScaNN, DiskANN, HNSW, and product quantization. These systems assume a single embedding space and do not address integration across models.

Domain adaptation and transfer learning

Domain adaptation transfers a model from a source domain to a target domain. This is related but different: it typically requires access to raw data and model internals, whereas LA2M is fully model-oblivious and data-oblivious.

Summary: What Makes This Work Novel

The Big Picture

The paper's contribution is a surprising and practically important observation: while global embedding geometry disagrees across models, local geometry is consistent. This is the local isometry hypothesis — a hypothesis the paper validates empirically (Jaccard index measurements, T-SNE visualisations) and exploits algorithmically (LA2M). The theoretical bound in Theorem 1 reveals exactly when and why the approach succeeds or fails, guiding cluster size selection. The result is a model-oblivious, data-oblivious integration algorithm that achieves dramatically better recall than prior baselines.

Open Questions

The paper leaves several open questions: (1) Can LA2M be extended to integrate more than two vector databases simultaneously? (2) Can the local isometry hypothesis be proved theoretically under some assumptions on the embedding models, rather than just validated empirically? (3) How does LA2M interact with privacy guarantees — can an adversary learn something about the raw data from the transformed vectors? (4) For very heterogeneous embedding models (very different dimensions, very different training corpora), what is the fundamental limit on how well integration can work?
