# Slow Books — authoring guide for Claude

This file documents conventions that Claude must follow when writing or editing
content under `books/*/chapters/` (book chapters) or `papers/*/index.html` (papers).

---

## Content types

### Books (`books/<slug>/`)
Multi-chapter structure. Each chapter is a separate HTML file under `chapters/`.
- `index.html` — chapter list / book home
- `chapters/chNN.html` — individual chapter pages
- `meta.json` — `{ "title", "subtitle", "description" }`
- `data-book` = book slug, `data-page` = `"chNN"` on `<body>`

### Papers (`papers/<slug>/`)
Single-page academic papers. The entire paper is one `index.html`.
- `index.html` — the full paper content
- `meta.json` — `{ "title", "authors", "venue", "description" }`
- `data-book` = paper slug, `data-page` = `"main"` on `<body>`
- Use `.paper-meta`, `.paper-abstract`, `.paper-references` CSS classes
- No `<nav class="chapter-nav">` (papers have no chapter navigation)
- Section structure: Abstract → numbered sections → References
- All `data-cid` values follow the `main-NNNN` pattern (step by 10)

## Math equations — TTS descriptions (required)

Every chapter page is read aloud by a TTS engine. LaTeX source is unreadable when
spoken directly (`\mu(A \cup B)` becomes gibberish). You must wrap every math
expression — inline and display — in a `<span class="tts-math">` with a
`data-tts` attribute that contains a plain-English reading of the expression.

### Format

**Inline math:**
```html
<span class="tts-math" data-tts="mu of A union B">$\mu(A \cup B)$</span>
```

**Display (block) math:**
```html
<span class="tts-math" data-tts="the integral of f with respect to mu, over all of X">
$$\int_{\mathcal{X}} f \, d\mu$$
</span>
```

### Rules for writing `data-tts` descriptions

- Write exactly how a lecturer would read it aloud to a student.
- Use plain words, not symbol names: say "mu of A" not "backslash mu open-paren A close-paren".
- Spell out Greek letters: "sigma", "lambda", "epsilon".
- For fractions: "a over b" or "the quantity a, divided by b".
- For subscripts/superscripts: "X sub i", "sigma squared", "e to the power n".
- For set notation: "A union B", "A intersect B", "x in S", "A subset of B".
- For limits/integrals: "the limit as n goes to infinity", "the integral from 0 to 1 of".
- Keep it concise — the listener already has context from the surrounding prose.
- Do NOT include punctuation that would sound odd when read aloud (no colons, brackets, etc.).

### Examples

| LaTeX | `data-tts` |
|-------|-----------|
| `$\sigma^2$` | `sigma squared` |
| `$\bar{X}_n$` | `X bar sub n` |
| `$P(A \mid B)$` | `P of A given B` |
| `$\frac{1}{n}\sum_{i=1}^n X_i$` | `one over n, times the sum from i equals 1 to n, of X sub i` |
| `$f = dP/d\mu$` | `f equals d P over d mu` |
| `$E[Y \mid X]$` | `the expected value of Y given X` |
| `$$\mathcal{F} = \sigma(\mathcal{A})$$` | `script F equals the sigma-algebra generated by script A` |

### What happens without a wrapper

If a `.katex` element has no `.tts-math` ancestor, the TTS player substitutes
the generic phrase "math expression". The page still works, but the audio is less
informative. Always provide a `data-tts` description.

## Block IDs (`data-cid`)

Every content block that a reader might want to comment on or have read aloud
must have a `data-cid` attribute. Follow the existing `chNN-NNNN` numbering
pattern in sequence (step by 10). The TTS player collects these in DOM order.

## Style conventions

- Use the existing box classes: `box intuition`, `box pause`, `box example`,
  `box warn`, `box definition`.
- All math rendered via KaTeX auto-render (delimiters: `$…$` inline, `$$…$$` display).
- Scripts included at the bottom of `<body>`:
  `/js/main.js`, `/js/comments.js`, `/js/tts.js` — in that order.
- CSS in `<head>`: `/css/style.css`, `/css/comments.css`, `/css/tts.css`.
